# Exporter case studies

Use the same exporter/policy unchanged across project graphs before drawing conclusions about Grapher core.

For each case study record:

1. source graph hash/publication;
2. exporter + policy versions;
3. candidate/eligible/rejected counts;
4. rejection reasons and example-kind distribution;
5. evidence-strength distribution;
6. leakage-group count/size;
7. a small auditable sample;
8. any extraction failure that may indicate a general Grapher modeling gap.

Do not tune the exporter to make one project look good. Change policy only when the reason is documented in `STUDY_LOG.md` and rerun prior case studies for comparison.
